# Bug Triage（缺陷分诊）

## Overview

缺陷不是「报个错」就完了。本 skill 把现象追成**可复现、可追溯、可修复**的结构化结论：复现 → 定位 → 定级 → 建议，并判断要不要回改需求/设计。

## When to use

- 测试失败、线上报错、用户反馈 bug。
- 研发全流程测试阶段，由编排器调用。
- 需要给开发一份「从哪改、为什么」的指引。

## Workflow

1. **收集现象**：报错日志 / 失败用例 / 复现描述；读 `.sdlc/test-cases.md` 与相关代码。
2. **复现**：最小复现步骤；无法复现则标注「偶发/需更多信息」。
3. **定位**：结合设计契约与代码，给出可能根因与怀疑文件/函数。
4. **定级**：按影响（数据/资金/阻断/体验）定 P0-P2。
5. **修复建议**：具体改动方向、注意点、回归范围。
6. **回写**：若根因是需求/设计漏洞，回写 `.sdlc/PRD.md` / `design.md`，并提示更新 AC。
7. **下一步**：修复后回归，最终交 `un-test-report` 汇总。

## Rules

- 结论要可操作，不接受「可能是并发问题」式含糊。
- 区分「代码 bug」与「需求/设计缺陷」，后者必须回写上游。
- 不擅自改代码，只给定位与建议。
